# Codebase audit — 7 September 2026

The highest-impact fixes address unintended Kanban moves, Agenda edits that changed schedules or lost drafts, continued access after allowlist removal, unsafe artifact responses, and an overwhelming Metrics page. These fixes are implemented in the working tree. The remaining release priorities are Agenda transaction safety, complete recurrence editing, and consistent recovery from failed requests.

## Scope and evidence

The review covered the application's 17 page entry points, the inventory of 55 route handlers, shared authentication, data loading, file handling, navigation, and scheduling code. Kanban, Agenda, and Metrics received deeper tracing from rendered controls through hooks to API/data operations. The source inventory contains roughly 360 TypeScript, TSX, JavaScript, and CSS files, including tests and scripts.

Evidence comes from source inspection, targeted regression tests, the full existing suite, TypeScript, ESLint, a production build, and browser checks using real components with local fixtures. The deployed Agenda page was inspected read-only; modified interactions were exercised locally. This is a codebase-wide review with focused workflow validation, not a claim that every production integration or every source line was exhaustively verified.

Existing staged and unstaged work, including Mobile Applications, Documents, and the broader Metrics improvements, was preserved. Passing tests for those areas validate the current combined working tree; they should not be attributed entirely to this audit.

## Prioritized remaining work

P1 means a data-integrity, access-control, or core-workflow risk worth addressing before a production readiness sign-off. P2 means a significant usability, accessibility, scalability, or maintainability improvement. P3 is cleanup or optional polish. No unresolved issue is labeled P0 without evidence of an immediate critical incident.

A later failure can leave the series incomplete. [Route](../app/api/agenda/events/[id]/route.ts) | Validate first; transact database changes; reconcile gateway job changes through retryable, idempotent work. Inject failures at each boundary and verify that existing schedules remain recoverable. | Large |

## Verification

- Targeted tests reproduced the repaired drag, rollback, recurrence, timezone, scoped-edit, request-order, artifact, and access-revocation failures before the fixes.
- Final combined Vitest run: **266 passed, 14 skipped** across **58 passing and 2 skipped test files**. The two skipped suites require configured PostgreSQL test databases.
- Production build: Next.js compiled successfully and generated the route output, including the Node proxy.
- The final build's TypeScript check passed. ESLint finished with **0 errors and 0 warnings**; `git diff --check` also passed.
- `npm audit --omit=dev --json`: **0 reported vulnerabilities** on the audit date. This describes known package advisories, not the application's complete security posture.
- Browser fixtures: Metrics at 1366×768 and 390×844, focused selection (six initially, five after deselection), Show all (twelve), keyboard controls, and chooser layout. Kanban keyboard move completed from To do to In progress, ticket opening worked, and narrow board scrolling stayed inside the page width. Agenda events opened with Enter, weekly editing retained Tuesday/Thursday, and simulated save failure kept the review and error visible. After the responsive fix, the Agenda dialog's content and scroll widths both measured 341 px; Day view also fit the narrow page without horizontal overflow. Temporary viewport overrides were reset.
- Fixtures use sample data. Run `node scripts/preview-audit.mjs`, then open `/tests/previews/audit.html` or `/tests/previews/metrics.html` on `http://127.0.0.1:4174`.

Live PostgreSQL-dependent tests, OpenClaw/gateway cron execution, Azure sign-in, real store providers, full screen-reader testing, and production load measurements were not exercised here. The database-dependent suites are explicitly skipped without their configured test databases. Auth membership checks add a database read to protected requests; validate their latency and outage behavior in staging. Existing streaming connections are not actively terminated when an account is revoked; subsequent requests are rejected.

Metrics visibility preferences are local to the browser, not synchronized between accounts or devices. Removing a card from the visible set unmounts it: its temporary per-card range/table controls and in-memory query cache reset when it is shown again. Saved metric definitions and the dashboard time range are unaffected. Preserving these transient card settings separately is a useful follow-up if frequent view switching warrants it.

## Suggested implementation order

1. Make Agenda series edits, occurrence materialization, dependencies, and gateway reconciliation safe as one vertical workflow, with PostgreSQL failure-injection tests.
2. Complete filesystem canonicalization and serialize initial-admin bootstrap.
3. Extend mutation isolation and hydration parity across Kanban; apply consistent load/retry behavior to Modules, Logs, Processes, Services, and Queues.
4. Profile large real-world boards and calendars, then batch queries/writes and reduce repeated rendering work.
5. Finish non-drag ordering controls, role-aware navigation, compact mobile layouts, and a complete assistive-technology review.

Accessibility references: [WCAG 2.2 dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) explains why a pointer alternative is still required; [dnd-kit sortable documentation](https://dndkit.com/legacy/presets/sortable/overview/) documents sortable keyboard sensors. [Next.js proxy documentation](https://nextjs.org/docs/app/api-reference/file-conventions/proxy) provides the framework context for the proxy build check.
